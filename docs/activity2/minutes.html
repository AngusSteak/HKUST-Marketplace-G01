2. Discussion of impediments and resolution

2.1. Chong and Chan edited the same DummyDataService at the same time, which caused repeated merge conflicts. It was split into one store per area (users, listings, deals, chat, reviews) before any screen work starts (#3).

2.3. The team had different ideas about when a deal changes state. Ho pointed out that only DealLifecycle should change a deal, and everyone agreed that screens must go through a store method instead of editing an object directly.

2. Discussion of impediments and resolution

2.1. The demo must run on the lab machines, which have JDK 21, and the build targeted an older release. Chong changed pom.xml to Java 21 and the project now builds with Java 21.

2.2. Adding the listing deleted column did not reach databases created before the change, because the schema only uses CREATE TABLE IF NOT EXISTS. It was decided to document one reset of data/ in the README instead of writing a migration.

2.3. Two copies of the app could open the same database and overwrite each other's changes. Chong will add a lock file so only one copy runs at a time (PR #94).

2.4. The screens depend on the deal lifecycle being final. The team agreed to freeze the model after this meeting, so the remaining work is screens, fixes and tests only.
